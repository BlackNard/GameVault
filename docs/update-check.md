# Update check and automatic updates

GameVault tells you when a newer version has been published and, like a store launcher, can keep itself up to date in place (see "Automatic updates" below; it can be turned off). The check adds a quiet notice to the **bell** in the title bar (a badge, no pop-up) and a status line in Settings > Updates, each with a button that opens the release page in your browser. The notice stays in the bell until you dismiss it (that version stays dismissed after a restart) or you update; the last result is kept in `Cache/update-notice.json`.

## The one request
- At every start, before the main window opens (it waits up to 4 s, then the window opens and the answer is shown when it arrives), when a running GameVault is brought back after 10 minutes or more, and every six hours while it stays open, GameVault sends **one anonymous GET** to `https://api.github.com/repos/BlackNard/GameVault/releases?per_page=20` through the shared polite HTTP client: fixed HTTPS address, 10 s timeout, 512 KB limit, no redirects, no cookies, no account.
- Nothing about you or your PC is sent: only a generic `GameVault/1 (desktop game library)` user agent. GitHub sees the usual network address of any web request.
- The time of the last check is kept in `Cache/update-check.txt`.
- Failures (offline, rate limit, odd answer) are quiet at start-up; **Check now** shows them in plain words.
- Turn it off in Settings > Updates ("Check for new versions when GameVault starts"). **Check now** still works. Stored as `checkForUpdates` in `Data/settings.json` (default on).

## Automatic updates (like a store launcher)
For the **installed** copy (the one the installer put on this PC; a portable ZIP or a development build only gets the release-page link) updates arrive on their own, without visiting a web page or running an installer by hand. Settings > Updates has "Download and install updates automatically" (on by default; off, or with the update check off, GameVault only tells you and waits for **Update now**).
1. **Background download.** When a check (at start, then every six hours while GameVault stays open) finds a newer release that carries its installer, GameVault downloads `GameVault-Setup-<version>-win-x64.exe` in the background, but **never while a game is running** (it tries again later). The file goes to `%LOCALAPPDATA%\GameVault-Updates` (outside the app folder).
2. **Verified.** HTTPS only from this repository's release; GitHub redirects release downloads to `release-assets.githubusercontent.com`, `objects.githubusercontent.com` or `github-releases.githubusercontent.com`, and only those are followed (at most three hops). The size must equal what the release lists and the file's **SHA-256 must match** the digest GitHub computed for the asset and, when the release publishes one, the `.sha256` file (if both exist they must agree). Anything failing, a file that is not a Windows program, or a download that stalls for 60 s is deleted. The verified file is recorded in `pending-update.json` and the bell shows "GameVault X is ready to install" with **Restart and update now**.
3. **Installed at a safe moment, without asking:** when you **close GameVault** (the tray Quit or closing the window when it does not stay in the tray), at the **next start** if it is still waiting (for example it lives in the tray), or at once when you click **Restart and update now**. Nothing that is running is interrupted: a running game or backup still gets the usual prompts before GameVault quits. Right before the installer starts, the file is **verified again** (size and SHA-256), so a file changed on disk in between is refused.
4. **How it installs.** The installer runs **over the same folder** with `/SILENT /NORESTART` (a progress window, no wizard, no administrator rights) and `/WAITFORPID=<id>` so setup waits for GameVault's own process to end; `/RELAUNCH=1` (only for Restart and update now and for the start-up case) opens the new version afterwards, a normal close does not reopen the app. The installer never touches `Data` or `Profiles` (checked by the installer lifecycle test in CI), so your games, saves, backups, notes and settings stay as they are.
5. **Failures never loop.** Offline, a mismatch or an installer problem leaves the current version in place; each installer start is counted and after three tries the update is left alone and the bell shows the release-page link. Old downloads are cleaned after two days (a waiting one is kept).

What the check proves: the file is the one this release published, byte for byte. It is **not a publisher signature** (the installer is unsigned, as before), so it protects against a damaged or swapped download but not against a compromised GitHub account; that is the trade-off of automatic installs, which is why they can be turned off. A file GameVault downloads itself carries no browser download mark, so Windows does not show the SmartScreen warning again for the update.

## Your data during an update
Updating must never damage your games, profiles or saves. Two independent protections run around every installer start:
1. **Safety copy first.** Right after GameVault has quit (the library is closed and no longer changing) it writes a **verified** copy of your data (all of `Data`, and `Profiles` without the large `Backups` and `Media` folders, in the same format as Settings > GameVault data > Back up GameVault data…) to `%LOCALAPPDATA%\GameVault-Updates\Safety`, together with a fingerprint of the **whole** library (every folder; every file by size and SHA-256; `Backups` and `Media` by name and size). The newest two copies are kept. **If the copy cannot be made or fails its check (for example the disk is full), the installer is not started**, the current version stays as it is, and the attempt counts like any failed start. Before you are even asked to restart, **Update now** checks that the folder is writable and there is enough free space.
2. **Compared after.** The new version, before it shows any window or opens the library, compares the library with the fingerprint. Identical: the check is only noted in the log (`Logs/gamevault.log`). Different (a file missing, changed or new): GameVault tells you how many files and the first few names, shows where the safety copy is, and lets you choose to open GameVault anyway or close it without touching anything. Nothing is deleted or restored on its own; to go back, use **Settings > GameVault data > Restore from a backup…** with the safety copy.

The installer itself still never owns `Data` or `Profiles` (CI installs, upgrades, uninstalls and reinstalls and requires the same fingerprint every time). Safety copies are kept until the next update replaces them; delete the `Safety` folder any time.

## What's new
After an update, the first start shows the notes of every version since the one used before (**New** and **Fixed**), once, when the app is free; a first install shows nothing. Settings > Updates > **What's new** opens them again. The notes ship inside the app (`GameVault.Core/ReleaseNotes.cs`); the newest version seen is kept in `Cache/whats-new.txt`.

## How versions are compared
`GameVault.Core/ReleaseVersion.cs` follows semantic versioning with an optional leading `v` and a fourth number: `0.1.0-preview.3` is newer than `0.1.0-preview.2`, `preview.10` is newer than `preview.9`, and `0.1.0` is newer than every `0.1.0-preview.N`. Draft releases and entries without a valid tag are ignored. A link is only accepted (and only opened, when you click it) if it points at `https://github.com/BlackNard/GameVault/releases/...`.

## When you prepare a release
The app's own version is `GameVaultVersion` from `Directory.Build.props` (shown by `AppVersionInfo.Current`), and the release tag is `v<version>`. **Raise it for every release** before the build the release is made from (see `docs/release-process.md`). Builds made after publishing and before the next raise report the published number and are not offered an update by themselves.

If the repository is renamed again, update `UpdateChecker.DefaultRepository`.
