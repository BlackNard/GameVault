# Safe restore and undo - issue #12

Restore a selected dated backup while keeping an independent way back. Use a same-window preview with editable per-source file/folder destinations, native browse buttons, an exact write/remove list and explicit confirmation. Current game must be stopped; use existing shared operation lease across launch, backup, pin/retention and restore. Destinations are local, narrow, nonoverlapping and outside app data/executables, without links, traversal or device aliases. File mappings must map exactly one file. Reinstall/move is supported through explicit validated mappings; destinations apply to this restore, and future automatic save configuration remains editable under Save sources.

## Approach
Keep ordinary dated snapshots immutable. Before any live replacement, stage and hash-verify both chosen payload and the full current destination trees into Profiles/<id>/RestoreRecovery/<operation-id> (independent of ordinary retention). A dedicated recovery document records targets, before files/directories, exact mutation list, payload hashes and absent files. Commit that document/directory, then atomically persist a Prepared restore journal before touching live data. A mirror-in-place loses rollback; wholesale folder swaps risk unrelated files and cross-volume paths. Use verified per-file staging and atomic replace/move plus allowlisted deletion instead.

## File ownership and preview
Selected paths are overwritten/created. Files absent in the selected set are removed by default only when earlier manifests for the same mapped source tracked them. New unrecognized files are kept and shown separately; the user can explicitly mark individual extra files for removal and preview again. Never recursively delete a destination tree. Missing destinations are permitted. File/directory collisions, conflicting mappings or malicious archive paths abort. Fresh execution must match the preview fingerprint of selected payload, destinations, current inventory/hashes, profile identity and requested extra removals; stale previews cannot write.

## Recovery and failures
Hold chosen source payload stable through verified staging, preserve existing destination data before replacement, and recheck paths/current expected bytes before every live mutation. Verify the final changed set. On partial failure attempt rollback only for successfully mutated files and only if they still match this operation's expected state; do not overwrite unrelated concurrent changes or write while an external game has started. Report RolledBack or RecoveryRequired specifically, with the recovery path intact. Prepared/recovery-required or protected journals block further launch/backup/retention mutations until recovery. A new undo operation may consume the corresponding protected recovery copy, preserving its current state in another independent recovery snapshot first. Historical recovery copies are selectable after restart and never ordinary retention candidates.

Crash during staging leaves a protected incomplete recovery folder without touching live files. Crash after Prepared leaves a durable guard and the full before copy available. An ordinary completed or rolled-back journal clears the guard. Nested undo journals retain RequiredRecoveryId pointing to the original unresolved restore, including failed rollback/cancellation/crash; only successful recovery of that authoritative target clears it. a failed final journal commit keeps it blocked for explicit recovery. Recovery documents are strict schema-1 protected JSON with bounded local paths/relative entries; no automatic deletion or silent recovery. No filesystem-wide transactional guarantee against external processes; optimistic rechecks and conservative recoverable-state reporting are required.

## Bounds, scope and validation
Reuse backup payload limits (32 mappings, 4096 files, 8192 entries/depth6 per observed tree, 4 GiB total per selected/before set). Recovery snapshots remain outside backup retention, including completed copies. No registry/cloud restore. Synthetic-only RED/GREEN tests for exact restores/deletions/unrelated files, stale preview, moved/missing targets, multi/file mappings, corrupted/unsafe payloads, preservation failure, partial rollback, rollback failure, crash guard/undo restart, cancellation/locks/junctions/external game/conflicts. One final focused review, full locked verify/publish, clean ZIP before private import, draft PR, green CI. Owner manual testing stays deferred.
