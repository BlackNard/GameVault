# System tray lifetime and backup alerts - issue #13

Keep GameVault running out of the way without losing sessions or post-exit backups. Use the Windows desktop NotifyIcon component as a thin adapter; a tested lifetime coordinator distinguishes hiding from quitting, and a tested alert policy coalesces backup failures. Native shell code is not part of automated headless tests.

Close-to-tray and backup notifications are optional schema-1 settings fields defaulting true for existing/new portable data; retain Midnight/Crimson and all existing settings. Show the behavior clearly in Settings and the sidebar, with a permanently available Quit GameVault action. Closing hides only when the tray is available. A failed tray setup keeps the window visible and explains how to quit; never leave a hidden app without a reopen path. Tray Open/left-click restores the existing window; tray Quit fully exits. No Windows startup registration is added.

Hiding does not navigate, dispose services, release the workspace lease, cancel discovery or flush/end a session. Notes/edit state remains in memory. Reopening must not repeat startup recovery/initialization. Explicit Quit (or Close with close-to-tray off) first brings the window forward, resolves existing dirty-operation guards, warns for active/starting sessions, and requests fresh checkpoints before stopping observation. Checkpoint failures require an explicit quit-anyway choice (default stay). Games are left open. Shutdown drains confirmed-exit backups before removing the tray icon and releasing the workspace. Quit requests coalesce; cancellation leaves runtime active. Deferred quit after a busy editor remains quit, not a later hide action.

Failure alerts retain latest actionable per-game diagnostics, deduplicate each failure episode until a successful backup, cap queued records and rate-limit native balloons. Do not display balloons while any tracked game is active; queue them until play ends. Settings can disable balloons without hiding diagnostics/menu actions. Tray menu and sidebar expose reviewable alerts; clicking a balloon opens the game's library details, with retry/save-source controls, while respecting unsaved notes. OS notification suppression is allowed; persisted backup status remains authoritative. No recurring automation/startup task is installed. Forced OS termination still relies on interrupted-session recovery and the latest successful checkpoint.

Verification uses pure coordinator/alert-policy fakes, synthetic settings compatibility/protection tests, explicit checkpoint tests and a fake launched session that survives hide and creates a post-exit backup. Cover duplicate quit/disposal, canceled quit, unavailable tray, cooldown/dedupe/queue bounds, play suppression and preference persistence. One final focused review; locked restore/build/tests/publish, clean ZIP before private data import, draft PR and green CI. All manual shell/tray/UI/native-dialog/game tests remain deferred to the owner final pass.
