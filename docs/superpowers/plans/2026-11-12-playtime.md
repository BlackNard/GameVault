# Issue #7 — Playtime and interrupted-session recovery

> Execute inline with superpowers:executing-plans; one focused final review. Owner performs all UI/UAC/real-game checks.

**Goal:** Persist measured play sessions and recover interruptions without adding unobserved time.

**Spec:** Issue #7; existing approved timing model (menus, pauses and AFK included, sleep/hibernate excluded); docs/design/ui-spec.md.

## Design and recovery rules

- Inject an awake elapsed clock. Windows uses QueryUnbiasedInterruptTime (100 ns units, excludes sleep/hibernate). Wall time labels never determine duration; clamp backwards wall timestamps to maintain valid start/end ordering.
- Each confirmed process starts a session with a stable GUID. Retain fractional elapsed ticks in an atomic `Profiles/<game>/Sessions/<session>.json` journal; project whole seconds into schema-1 statistics by replacing/upserting the same session ID. Never append a second record for a checkpoint/retry.
- Save a checkpoint every 10 awake seconds and on confirmed exit or observation shutdown. Journals are committed before statistics; recovery reconciles a journal whose statistics write was interrupted. Preserve adjustments and unrelated sessions. Refuse corrupt/recovered/future data writes, retain diagnostics, and never kill games on storage failure.
- Journals retain Active/Completed/Interrupted state, process identity, target path, optional process-group name, and recovery count. Completed journals remain as recovery metadata. Normal close leaves the game open and marks observation Interrupted. Crash recovery finalizes Active at the last saved observation, never at restart time.
- If a verified same process/group still runs at startup, reopen observation and resume the same session ID from a new awake-clock baseline. Duration before the last checkpoint is kept; time while GameVault was absent is excluded. Repeated recovery is idempotent. If exited, PID reused, or identity cannot be verified, retain only the checkpoint duration and mark Interrupted with a visible notice.
- Name no-kill Windows process groups with random Local names and explicit user-SID permissions so same-account observation (including approved elevated games) can be reopened after the launcher exits. Transfer the name with existing read-only helper handles. Never launch or request elevation merely to recover.
- Show live session elapsed and total in the existing library; one UI refresh per second only while a session is active. Detailed history/charts/manual corrections remain #8, save discovery/backup #9/#10, background tray continuity #13.
