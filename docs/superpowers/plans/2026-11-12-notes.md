# Notes and Reviews Implementation Plan

> Implement inline with superpowers:executing-plans; one focused final review. The owner approved the visual Read/Edit layout on 2026-11-12. Continue within the established issue branch; no new workspace or extra approval gate.

**Goal:** Save session notes and completed-game reviews, read/edit them, and export individual or bulk Markdown/PDF copies.
**Architecture:** Separate schema-1 note sidecars use the existing atomic store/gate. Shared session/entry catalog and export models keep WPF focused on navigation, dirty protection and native pickers. A Windows PDF renderer provides offline paginated documents.
**Tech stack:** .NET 10 WPF; existing strict JSON storage; PDFsharp/MigraDoc WPF 6.2.3 (exact MIT tag, notices retained), subject to Unicode/pagination verification.
**Spec:** docs/superpowers/specs/2026-11-12-notes-design.md; approved interactive layout, including Read/Edit modes.

## Global constraints
- Preserve profile/session identity, measured durations, recovery journals, actual saves, and both themes.
- Offline local generation, no real-game/UI automation; owner tests native UI.
- Recovered/corrupt/future documents stay protected. Never package personal test data.

## Review focus
- Metadata missing/corrupt/active: never allow editing an ongoing session or claim normal completion.
- Draft edits during navigation/export/close: no silent loss; saved-version export explicit.
- Hostile titles, Unicode/long lines, existing destinations: preserve content and prevent overwrites/path escape.
- Partly unreadable libraries/destinations: accurate exclusions/partial failure, never total success.
- Session lifetime while note window open: refresh before writes; no timing mutation or shutdown races.
