# Game library implementation plan — issue #5

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline, with one focused final code review.

**Goal:** Manage a persisted local game library with native browsing, optional copied cover art, status organization, and reversible removal.

**Spec:** Approved docs/design/ui-spec.md; issue #5; issue #4 storage safety.

**Architecture:** A testable Infrastructure LibraryService validates/canonicalizes paths and coordinates profile/cover operations with the existing repository. WPF supplies native pickers and decodes cover images, then renders the library with the approved Midnight/Crimson resources. Existing schema 1 profiles remain compatible; optional art is a separate cover.png, never a required new JSON field.

## Constraints

- No game launching/timing/real save backup or restore yet; these remain later tickets. Do not show invented statistics or protected-save claims.
- Game executables must be absolute existing .exe files for new/changed paths. Unchanged missing installations retain their editable records and show a warning.
- New entries default to Not started and inherit backup defaults. Name/status/path editing preserves ID, history, backup preferences, and existing backups.
- Duplicate canonical executable paths, including archived profiles, are detected. Restore retained profiles explicitly rather than creating duplicate history.
- Removal sets IsArchived only. No permanent deletion or game uninstall action.
- File/folder picker cancellation preserves typed values. Executable selection autofills an empty/default working directory but preserves a customized folder.
- Cover art is decoded from bounded local files, normalized to a small PNG, copied into the profile, and loaded without retaining source file locks. Cover-write failure after profile commit is reported accurately as a warning, not a failed profile save.
- UI work uses asynchronous services, guards overlapping writes, preserves filters/selection, and holds the workspace lease while an operation is pending. Owner performs all manual UI/native-dialog checks; no desktop automation.

## Review focus
